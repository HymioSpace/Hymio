# 关联记忆：产品与技术调整方案

Status: Implementing — 产品方向已确认；当前交付有界关系图、领域提炼和运行时装配。2026-10-24。

本方案调整 feature31 的分类、星图与提炼策略。本文只提出设计，不改变运行中的接口、数据或部署。

## 1. 产品模型

记忆是有版本、有来源的卡片关系网络。原始资料、理解和概述是内容角色，不是限制连接方向的树层级。任意两类卡片之间都可以存在合理关系；没有关系也完全正常。分类用于浏览，不是图的分区约束。

- 理解：模型整理的结论，按主题分类；展示标题、简述、必要状态与 `…`。
- 足迹：保留的原始资料，按真实来源筛选；不要求用户给原文选择主题分类。不是聊天记录全集。
- 概述：理解页顶部的长期背景摘要，有自身版本和支撑关系；属于网络中的内容，不是另一个孤立配置。
- 星图：同一数据的关系浏览视图，理解、原始资料、概述均可作为中心，支持跨角色与跨主题连接。
- 来源、文件格式分别建模。例如浏览器是来源，网页/图片是内容形式；连接器名称作为来源明细，不把图片当作唯一来源。

关系应可解释，不把同主题直接变成事实关系；主题聚合轮廓只用于布局，与真实边明确区分。

## 2. 一级页面与操作

记忆标题 + 纯加号；搜索；理解/足迹双 tab；星图入口。没有固定宠物占位、聊天引导或排列一整排编辑按钮。

理解页顶部显示约三行概述，可原位展开。下方分类筛选与理解卡片。足迹页改为来源筛选与时间排序，不显示工作/学习/生活。

卡片一级只显示标题、短摘要、必要元信息与 `…`。编辑/纠正、查看关联、查看变更、停止用于回答、删除等放入按卡片角色生成的菜单；只展示已实现和可执行的操作。停用影响检索与概述依赖，不能只隐藏 UI；删除明确区别原始资料删除与仅移除关系。

点卡片原位展开正文与相关内容；长原文在一个阅读面板内切换，不叠加 sheet。Web 使用右侧 inspector。筛选、滚动位置、所选卡片、图布局与图视口切换后保留。菜单不是所有核心浏览操作的唯一入口：点卡片即可读内容，点关联计数可看关联。

## 3. 星图：信息更丰富，默认仍清楚

### 全景

默认展示当前范围的代表卡片与主题分布。标明“当前展示 N 张”和范围，不把局部加载伪装成完整记忆。主题区域使用淡色背景与标题，不用虚假连线。跨区域的真实连接保留。

首屏建议预算：iOS 约 12 个节点 / 18 条边，Web 约 24 / 36；这是待性能和可读性验证的起始值，不是模型能力上限。服务端提供未展开计数和游标，点 `+N` 获取更多，不静默丢弃。

### 聚焦

点任意卡片：突出该卡片及一跳邻居，弱化其余内容；选中关系显示方向、含义、建立原因和来源。节点可表现为文字、图片缩略图或文件预览，但必须有标题、角色标记和无图片回退。

图不是固定的树：原文可连接原文，理解可关联理解，概述可关联理解，跨主题同样有效。点邻居可以换中心；“回到全景”一步返回，保留视口历史，避免不断 push 新页面。

关系标签默认只显示所选节点的关键边；不在每条线上铺文字。线型区分已发布、待确认和历史失效，不仅靠颜色。没有选中时重视结构，有选中时重视语义。节点大小不代表事实可信度。

### 变化

提供轻量“最近变化”筛选，显示新增/修正/待核对标识。点某个变化，在同一 inspector 中显示旧结论、新结论、触发资料及受影响关系。完整时间轴回放后置，第一版先做版本差异与历史关系查看。

### 一例贯穿列表和图

合成示例：原始手记“下午咖啡影响入睡”支撑理解“下午避免咖啡”；这条理解与“晚上十一点睡觉”通过“关联”相连，理由是同一原文明确讨论饮品和睡眠。另一条手记可“补充”前一条。不能仅凭模型常识宣称饮食导致用户睡眠疾病。

用户新增“现在少量咖啡不影响睡眠”后，原始资料保留；先出现待核对的变化，审查相关理解和概述，再原子发布新结论/关系。图展示变化，不偷偷覆盖原文，也不由一次变化遍历修改全网。

### 空态与异常

- 没有资料：小型空态与加号，不展示虚构图。
- 有资料无理解：足迹可读，理解显示等待整理。
- 无关联：仍显示所选卡片，说明尚无关联；不制造连接。
- 搜索无结果、离线读取失败、部分邻居读取失败分别呈现；失败不当成空。
- 有矛盾或更新失败：保留已发布版本，标记待核对/更新未完成，不伪装成功。

## 4. 已核对的实现差距

- Nostalgia `Artifact.references` 指向原始 record，`Artifact.links` 是 artifact ID 列表；已有 artifact-to-artifact 导航，但没有统一的有类型任意端点关系协议。
- Nostalgia commit 已校验引用、链接和原始记录状态，可以扩展现有发布事务，不另造独立写入生命周期。
- Hymio 的 graph UI 目前只渲染理解到原文的一跳关系；这比现有 links 能力更窄。
- `recall` 目前是文字子串查询与精确读取，无邻域展开；`remember` 保存原文与提炼候选，不做关系更新事务。
- dreaming prompt 规定 links 仅用于导航，现有 proposal 只有 artifacts / record_states，无关系操作。
- `/context/assembly` 已有 `_core` 长期背景和 dynamic injection（`_index` + pending buffer）；不能把这三个内容统称为全部已进入 system prompt。当前页面未展示它们。此次未核验生产中每次 Oath 请求的最终上下文，因此“实际使用”需由运行时回执证明。

## 5. 服务边界与存储

Nostalgia 是唯一关系与卡片事实源：管理关系实体、反向索引、版本、查询和原子发布。Hymio 负责采集、用户权限、产品投影与界面；Oath 负责通用运行与上下文装配扩展，不能复制 Nostalgia 核心或在 Hymio 新建第二张权威关系网。

优先扩展 Nostalgia 当前存储，不默认引入图数据库。需要按用户、源端点、目标端点、关系类型、有效版本建立可查询索引；JSON 字段不足以支撑每次遍历。规模和查询性能达到阈值后再讨论存储迁移。

### 统一端点与关系（拟议协议）

NodeRef = {kind: record | artifact, id, revision}。record 引用保留 root_id 与实际 revision；artifact 使用稳定 ID 和发布 revision。概述也是 artifact，UI 不展示内部 key。

Relation = {id, from, to, type, direction, status, origin, rationale, evidence_refs, valid_from, valid_to, revision}。

- type 首版：supports（支撑）、supplements（补充）、contradicts（矛盾）、supersedes（取代）、related（相关）、navigates（历史导航）。不提供无约束自然语言类型。
- role 不限制端点组合；每种关系仍有语义校验，不能把指向网页的边当成用户事实证据。
- supports：支持方 → 被支持方；supersedes：新 → 旧；contradicts / related 对称并规范化端点，防重复；导航不自动升级为支持关系。
- status：proposed / active / disputed / retired。模型提出关系不等于用户确认；用户确认信息单独保留。
- origin：user / model / import，加 invocation / source provenance；rationale 是可读的简短理由，不存模型推理过程。支持关系的证据必须存在，模型自己生成的结论不能循环自证。
- 普通图允许环；supersedes 等关系类型需禁止环。删除、停用与失效传播按语义处理，不级联删除所有邻居。

所有关系和节点必须同用户授权；双端点、证据、版本、关系类型、有效时间与请求配额在服务端校验。邻居计数也不得泄漏无权限或已删除内容。

## 6. 写入、检索、更新策略

### 保存

原文及来源首先可靠保存，返回 saved + synthesis_pending。以原始写入事件为幂等触发，获取相关候选：文字查询、现有双向邻接、同根版本等；向量召回可后续作为候选检索补充，不作为第一版前置依赖，也不把关键词未命中解释成没有关联。

整理器读取候选完整正文和必要依据，提出 node / relation patch。重复、补充、矛盾、取代分别处理，保留稳定 ID。服务端校验后，在同一个 dream/发布事务中更新理解、关系、受影响概述和索引。原文已保存但提炼失败是可恢复状态，不回滚或丢弃原文。

### 检索

查询 → 命中种子 → 有预算的双向邻域扩展 → 读取必要原文 → 返回上下文与关联路径。

建议默认 depth=1、最多 20 节点，必要时显式扩展到 depth=2；服务端有独立硬上限、deadline、字符预算和去重/环检测。active 为默认，但和当前种子直接相关的 disputed 冲突必须显式提示，不能因过滤被隐藏。历史 superseded 默认不作当前事实，可作为变化解释读取。

按文字相关性、关系含义、有效性和时效排序；关联度不等于置信度，旧资料也不因旧自动失效。返回 truncated / next_cursor / snapshot_version 和每项入选原因，模型不能把截断结果称为全部记忆。

### 更新与纠正

先记录用户纠正或新版本原文，计算受影响集合：直接依赖边 + 有预算的间接依赖（概述等）+ 必要语义候选。相关边触发复核，不意味着内容都必须改。

提交包含 base_version、精确读集 revision、节点/关系变更集、幂等 operation_id。并发变化导致 precondition_failed 时重新读取并重新评估，不盲目重放模型 patch。成功返回 published_version 与受影响计数。

单次事务无法完成的影响范围必须保留 durable pending 工作和失效状态；下游不能继续无标记地使用旧摘要。失败可恢复，同操作不重复建边。用户纠正不会悄悄被后续模型推断覆盖。

停止用于回答应即时从检索/装配排除，并使受影响概述失效或重建；旧运行快照按保留策略管理。删除需要同时清理关系、检索索引、缓存和读取权限，不把逻辑版本历史当作永久保留已删除私密正文的理由。

## 7. API、工具、prompt 调整

以下为拟议接口，需在 Nostalgia 正式协议确定后实现；Hymio 只代理与做展示投影：

- graph/query：scope / seed / relation_types / status / depth / cursor / snapshot_version → nodes、edges、边界计数、truncated。
- graph/changes：版本间节点与关系变化；分页保持同一快照。
- context/retrieve：query + bounded expansion → 内容、证据与路径。
- context/change-proposals：用户纠正/关系编辑的幂等提案，返回 pending / published / failed；不开放任意数据库 patch。
- context/overview：长期概述、理解导航与新资料状态的产品投影，缺少 `_core` 时返回未形成，不能生成一段 UI 假概述。
- context/usage：准备装配快照，以及按 run_id 查询实际装配回执；无回执只能说“准备带入”。

`recall(query)` 保留旧行为兼容，扩展 related / retrieve 动作；明确返回关系方向、状态和截断。`remember(summary,text,...)` 保留原文和提炼候选契约，关联处理由服务端统一调度，不能仅靠模型记得先查再写；可携带已读目标作为 hint，服务端重新验证。候选 category 不用来分类原始资料。

用户明确纠正时使用受控 revise 提案（可作为 remember action 扩展，最终 schema 待定）；涉及删除/停用的授权区别于日常自动整理。未知结果先查询原 operation_id，不生成新操作补写。

dreaming proposal 增加有版本的关系 changeset、依赖读集和概述更新，按原文验证候选。system prompt 与 context skill 明确：记忆不是全集、关系是有来源的断言、相关不等于支持、矛盾需核对、保存不等于发布、截断不等于完整、检索内容不授予执行权限。

装配：稳定长期背景 + 动态导航/近期补充 + 本轮相关子图；三者受独立预算约束并去重。近期未整理资料必须标明 pending/来源，不能自动当作已验证事实。Oath 通用 builder 记录实际加入的 ID/revision、截断、装配版本和预算回执；内容不作为高优先级可执行指令。回执可验证“用了哪些记忆”，不宣称能证明模型内部注意了什么。

## 8. 兼容与迁移

references 按证据方向投影 record → artifact supports；links 投影 artifact → artifact navigates，保留历史语义，不能编造其关系理由。迁移只建立可证明的关系，不重写原文。迁移 ID 确定性生成并支持重复执行。

先只读投影验证，再版本化发布关系协议。v1 客户端继续获得 references/links 兼容投影；新的关系实体是唯一权威，不长期双写两套独立真相。旧写入路径由服务端适配到同一事务。未升级服务必须 capability 检测，前端回退为现有引用浏览并说明能力范围。

历史原始资料的 category 字段保留兼容，但足迹不再拿它筛选；新直接保存不询问分类。关系网络没有强制拓扑分层。历史 `_core` 为空时展示真实空态，而不是拿所有卡片首句拼接冒充概述。

## 9. 分步实施与验收

1. Nostalgia：关系实体、双向查询、原子版本、并发与幂等、迁移和失效机制；先用合成数据验证 record↔record、artifact↔artifact、混合端点、跨分类与循环图。
2. Hymio/Oath 扩展：关联检索、更新提案、受影响集合、概述维护、实际装配回执，保持项目边界。检索与更新不能只改 prompt。
3. 双端：概述与来源筛选、菜单、普通卡片展开；接同一 graph query 做全景/聚焦/变更与返回定位。可读列表是星图等价入口。
4. 第一版交付有限全景和聚焦、一步换中心、边解释、最近变化与差异；后置完整时间播放、无限自由布局、自动复杂聚类和大规模语义召回。

验收必须包含：新增关联但不重复理解；纠正只更新应受影响卡片与关系；概述同步失效/更新；冲突不会静默消失；停用内容不再注入；并发纠正无覆盖；未知结果重试不重复；删除无残留可读引用；权限不跨用户；分页快照一致；pending 可恢复；子图截断明确。

UI 验收：同一 ID 在列表/星图/详情的正文状态一致；任意角色可作为中心；至少一个非树形跨主题合成场景；iOS 真实模拟器检查中文对齐、44pt 触控、Dynamic Type、深色、VoiceOver、减少动态；Web 键盘选择/缩放/返回与窄屏。性能预算须实测首屏、扩展延迟与节点规模，再确定上限。

## 10. 视觉约束与实现取舍

浅色背景 #F5F7FB，表面 #FFFFFF，正文 #17243B，次级文字 #596579，主色 #245CDB；深色使用独立语义色，不复用浅色透明度。iOS 系统字体，正文 17pt，标题 22/28pt；图标签允许 13pt，完整内容进入 inspector，支持放大和等价列表。落地前计算各状态对比度，不把设计图视为可访问性测试。

布局用稳定的有界邻域排布和位置缓存，避免持续漂移的力导向动画。iOS 可复用 SwiftUI 节点/Path 连线，在有界规模内加平移缩放；Web 先用 SVG 边 + DOM 节点，密度达到实测阈值再评估 Canvas。只在换中心时做短暂位移，减少动态时直接更新。

设计依据：apple-design 的 sheets.md / Nonmodal alternatives 建议尽量在主界面展示信息，generative-ai.md / Outputs 要求用户可修正且能看到何时生效。本方案的任意关系网络与版本策略来自本产品要求，不是 HIG 的规定。

## 当前交付边界

关系存储复用版本 details，查询目前在同一事务中构建有限用户快照；专用邻接索引、大规模图优化和完整版本差异面板仍需后续实现。当前支持最近变化标记、单跳/两跳查询、关系解释和原始资料纠正提案，不开放任意删除或停用操作。实际界面按 memory-product-refinement.md 默认原始资料，星图放在我的理解内。
