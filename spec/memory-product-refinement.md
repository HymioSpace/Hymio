# 个人理解与记忆：产品约束调整

Status: Accepted direction; implementation in progress. Supersedes conflicting presentation and taxonomy choices in feature31/32.

## 产品入口

记忆默认展示「原始资料」，按来源浏览；另一页签为「我的理解」。该页顶部用「我对你的理解」呈现助理对用户的整体认识，下面是具体提炼。星图只在「我的理解」内作为浏览方式。更多操作收进省略菜单。产品不展示“注入”“准备带入”等运行机制术语。

界面使用清晰自然的助理口吻、舒适留白和轻微色彩，避免技术控制台感，也不加装饰性聊天引导或大幅吉祥物。

## 三种分类职责

1. 领域类型是提炼协议中的有限集合，初版16种：饮食偏好、语言与表达、沟通协作、作息习惯、学习方式、兴趣爱好、工作背景、当前项目、目标计划、重要决定、人际关系、个人背景、出行偏好、消费偏好、健康相关、其他。内部使用稳定 key；缺少依据就不生成。健康相关仅保留明确提供的信息，不推断疾病。
2. 展示标签由模型根据内容生成并归并同义词，例如生活、工作、学习；允许跨标签。标签负责浏览分组，不是事实内容，也不作为硬检索边界。
3. 检索使用具体内容、稳定领域类型、实体/别名及卡片关系。生活/工作等宽泛标签不承担检索策略。一个卡片可以有多个领域与标签，关系不受分类限制。

## 上下文装配

第一部分为简短的整体理解，保留时间范围和不确定性；第二部分为极少量关键约束，必须有来源且真正影响助理决策，例如用户明确要求长期遵守的沟通规则。第三部分是领域检索索引：领域名、涵盖内容、稳定卡片入口或实际可执行的查询提示，如饮食偏好 → 查询具体忌口/饮品偏好与相关原文。不能只提供“生活”这样无检索价值的目录。

具体任务通过索引检索相关卡片、扩展关系并按需读取原文。原始资料不全量注入，普通偏好不全部升级为关键约束，第三方材料不能冒充用户陈述。索引与理解使用同一发布版本，停用/纠正需要同步维护。展示的「我对你的理解」与实际整体理解数据一致，但无需向用户展示内部 prompt。

## 实施顺序

先纠正双端默认页与文案，再修改提炼 schema、provider 校验与迁移兼容；随后完善整体理解/关键约束/领域索引装配及检索，最后在真实界面检查一级页面和星图的渐进展开。没有通过真实运行验证前，不把这些调整描述为完成。
